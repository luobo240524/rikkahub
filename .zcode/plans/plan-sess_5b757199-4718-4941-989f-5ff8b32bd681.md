# 语音通话三项改动实施计划

## Context

用户对语音通话/语音发送提出三项需求:①通话可挂后台继续(退出页面/退到桌面都不中断);②语音条改微信式"长按麦克风说话",当前 bug 是录音一开始麦克风按钮就被隐藏(条件 `!asrState.isRecording` 把按钮移出组合),松手时没法点它发送;③通话中途断开、模型无反应——根因是生成失败会把消息队列 `pause()`,之后每轮 `enqueueVoiceMessage` 直接抛"队列已暂停",且控制器无任何自动重试,只有手动重试按钮。

## 改动一:通话后台挂起

通话目前是 NavBackStackEntry 级 VM(`VoiceCallVM`)+ Compose 页面,离开页面/退后台即失效。改为**全局单例会话 + 前台服务(microphone) + 悬浮球**:

1. **新建 `VoiceCallSessionManager`**(Koin single,`ui/pages/call/VoiceCallSessionManager.kt`):把 `VoiceCallVM.kt` 的全部逻辑迁入(prepare/startCall/stopCall/handleHangupRequest/enqueueText/countCallRounds、latestReply/streamingReply 流、callId/incoming 标记),另:
   - 自持 `CoroutineScope`(用现有 `AppScope`)+ `VoiceSessionController`;
   - **TTS 实例从页面迁入 manager**(现 `rememberCustomTtsState()` 在页面组合销毁时会 dispose,最小化即断声;manager 内直接用 `CustomTtsStateImpl(context.applicationContext, settingsStore)` 并在 scope 里监听 settings 变更更新 provider,speak/stopSpeaking lambda 一并迁入);
   - **createCallAsr 迁入 manager**(注入 OkHttpClient,沿用 VoiceCallPage.kt:413-454 的音频焦点包装);
   - eventBus 的 `VoiceCallHangupRequest` 监听从页面迁入 manager scope;
   - `startCall` 返回 String?(错误文案,页面对应的 blocked 检查逻辑迁入);暴露 `callStartedAtMs`/`targetAssistantId`/`assistantName`/`assistantAvatar`。
2. **新建 `VoiceCallForegroundService`**(仿 `ChatGenerationForegroundService` 的 acquire/release 静态入口):
   - Manifest 加 `<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MICROPHONE"/>` + `<service android:foregroundServiceType="microphone"/>`;
   - 通话中通知"通话中 · {助手名}",contentIntent 走新 action `ACTION_RESUME_VOICE_CALL` → RouteActivity 仿 259-262 行处理,导航到 `Screen.VoiceCall`;
   - onDestroy 时若 manager 仍活跃 → `stopCall()` 兜底(保证挂断事实落库)。
3. **`VoiceCallPage.kt` 改绑定**:`koinInject<VoiceCallSessionManager>()` 替代 koinViewModel;`LaunchedEffect(assistantId)` 里 `state.isActive` 时跳过 prepare/auto-start(重进页面只回绑);返回箭头与 `BackHandler(通话中)` = 仅 `popBackStack()` 最小化(不再 stopCall),挂断红钮才 stopCall;计时改用 `callStartedAtMs` 换算(回绑不再归零);保留 TA 挂断事件 pop 页面的观察。
4. **新建 `VoiceCallMiniBar` 悬浮球**(仿 `MusicMiniBar.kt` 52dp 可拖拽球):显示条件 `phase != Off && 当前路由 != VoiceCall`,挂载在 RouteActivity NavHost 之后全局层;球面用助手头像,点按 → `navController.navigate(Screen.VoiceCall(manager.targetAssistantId, false))`。
5. **删除 `VoiceCallVM.kt`** + ViewModelModule.kt:84 注册(引用处仅剩注释,顺带更新)。

## 改动二:长按麦克风按住说话(ChatInput.kt)

1. 麦克风按钮(ChatInput.kt:527-545)改手势:`Box + pointerInput(awaitEachGesture)`——按下后 200ms 内抬起=误触,toast 提示"按住说话,松开发送";超过 200ms 开录(`startVoiceRecording()`+触感反馈),期间追踪指针,**上滑超过 80dp 进入取消模式**,松手=取消(`cancelVoiceRecording()`)/发送(`stopAndSendVoice()`),系统打断手势=取消。
2. **显示条件去掉 `!asrState.isRecording`**(bug 根因),改为 `onSendVoiceMessage != null && SendVoice 工具 && !voiceState.isActive`;录音期间按钮保持可见并变红。
3. 录音条文案(446 行)"再点麦克风发送" → "松开发送 · 上滑取消",取消模式时显示"松开取消"并标红。
4. AsrButton 可见性加 `&& !recordingVoice`(避免按住说话时多出转写按钮);SendButton 的 AnimatedVisibility 条件加 `!recordingVoice`(580 行)。
5. 加 `DisposableEffect`:页面离开组合时取消未发送的录音(防泄漏);权限未授权时按按下先 `requestPermissions()` 不开录。

## 改动三:修通话中途断开/模型无反应

1. **ChatService 不再因通话轮失败锁队列**:
   - `sendQueuedMessage` catch(519-525 行):检测 `content` 是否 voice_call 轮,是则跳过 `session.messageQueue.pause()`(reply 异常照传,由控制器处理);
   - `handleMessageComplete` onFailure(929 行):`voiceCallTag != null` 时同样跳过 pause。
2. **VoiceSessionController 自动重试**(`VoiceSessionController.kt`):
   - `submitted` 通道携带话语文本 `Pair<String, Deferred<String?>>`,回复观察协程失败时 `Event.Failed(e, retryText)`;streaming speakingJob 的 catch 同样带上当轮文本;
   - 主循环 `Event.Failed`:带 retryText 且 `genRetries < 2` → 退避重发同一句(delay 800ms×次数,重建 speakingJob);retryText 为空(ASR/监听失败)且 `asrRetries < 2` → join 并清空 capture,循环顶部重建 ASR 重新听;计数在收到 Reply/非空 Utterance 时归零;超限才落 Error(手动重试按钮保留)。
   - 效果:2 分钟静默超时、ASR 断连、单次生成失败都不再直接杀通话。

## 验证

- `./gradlew assembleDebug` 编译通过;`./gradlew lint` 无新增严重问题。
- 手动:①通话中按返回键/最小化 → 悬浮球出现,聊天正常,点球回通话页计时连续;②通话中按 Home → 通知栏通话通知,数秒后说话仍能识别回复;③挂断/TA 挂断 → 球与通知消失,聊天页有通话记录卡;④按住麦克风说话 → 按钮全程可见,松手发送语音条,上滑取消;⑤断网制造生成失败 → 通话自动恢复不弹"出错了"。

## 不改动

聊天页免提语音模式(VoiceMode/ChatVM.voiceSession)独立链路、`VoiceMessageBubble` 渲染、`ChatPage.onSendVoiceMessage` 消息构造均保持不变。
