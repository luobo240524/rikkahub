## Context
r361 验收暴露四类问题：成年宠物绕过了只覆盖孵化蛋的冷却链；封面首屏头像加载依赖异步壁纸链和单次 Image probe，导致月团头像初始空白；留灯缺少“碎碎念/一份信”的中间入口、邮局和预约送达模型；打卡页在 edge-to-edge 下没有 IME inset，键盘覆盖表单。此次不做 UI-only 补丁：宠物冷却改为服务端、按宠物独立判定，避免继续在前端演示层打补丁。

已确认的产品语义：
- 成年宠物同类动作沿用孵蛋规则：对方直接喂食/玩耍/梳毛各 4 小时冷却；TA 照顾 6 小时冷却；按宠物独立计时。
- 信件是单个未来送达时刻；到点前封存，到点解锁后长期保留。
- TA 与对方都能创建信件。
- 到点既在邮局解锁，也发系统通知；采用 WorkManager 尽量准时，不引入精确闹钟权限。

## Implementation Plan

1. **宠物冷却根因修复（服务端真源）**
   - 在 `WorldPetEventDAO` 增加按 `assistantId + petId + actor/action` 查询最近事件的接口，避免当前事件表跨宠物取最近记录；同时增加按宠物取连续照顾事件的查询。
   - 在 `WorldRepository` 抽出统一的宠物照顾策略：所有 `feedPet`、`playPet`、`groomPet`、`taCare` 在修改粮仓、成长、性格、写日记前先做冷却判定；对方动作使用 4 小时，TA 照顾使用独立的 6 小时类别；失败返回现有 `PetOpResult.Failed("cooldown")`，不发生任何状态变更。
   - 修正成长收益和日记去重的范围：连续动作按同一只宠物统计；`logPet` 去重也带 `petId`，避免另一只宠物或非照顾事件污染计数。保留孵化蛋现有动作语义，不让新成年宠物策略改变破壳门槛。
   - 扩展 `PagePet`/`toPagePet` 返回成年宠物的冷却键，前端统一渲染按钮禁用、剩余时间提示；`pet.html` 不再只对 egg 设置冷却，所有动作均以桥返回的真实 state 为准。失败时不先做不可逆的粮仓/成长/动画演示，或由真实 state 完整回滚。
   - 补充 repository/DAO 单测：同一宠物同类连点被拒、换动作规则独立、两只宠物互不影响、TA 6 小时规则、失败不扣粮不增成长；核对现有 egg 冷却回归。

2. **封面头像首屏稳定加载**
   - 在 `WorldJsBridge.resolveAvatarUrl` 中区分“可转换的本地图片”和“不可访问的原始路径”：读取失败时返回可用的空值/emoji 回退，不把 WebView 无法加载的 `content://`/本地路径继续交给页面。
   - 在 `cover.html` 把头像应用和壁纸取色解耦：头像 probe 有 `onload`、`onerror` 和稳定 fallback；首屏先完成头像/名称落位，不依赖壁纸采样结束才可见。
   - 重构初始 `applyWall`/boot 失败路径：壁纸资源或 canvas 取色失败时仍执行 `playIntro()` 和显示内容；首次加载与点击换壁纸共用可重入的安全包装，避免“点一下后才触发”的假修复。
   - 用月团图片头像、emoji 头像、无效本地路径三条路径验证：首屏可见、无资源时保留字/emoji，不阻塞封面动效。

3. **留灯中间入口、信件数据与邮局**
   - 先按项目硬规则制作 HTML 预览并用浏览器截图确认新视觉：`envelope.html` 作为留灯入口的并排页，包含“碎碎念”和“一份信”两个入口；“碎碎念”进入现有 `thoughts.html`，“一份信”进入 `postoffice.html`。不直接在 Compose 中猜视觉。
   - 新增独立 `world_letters` Room 实体/DAO/页面 DTO，字段至少包含 `id`、`assistant_id`、`author(user/assistant)`、`content`、`created_at`、可空 `scheduled_at`、`notified_at`、`opened_at`。采用独立表，不污染现有碎碎念抽屉/抽取逻辑。
   - 将数据库升级到 v40，新增 `Migration_39_40`、注册到 `AppDatabaseFactory`、加入 `AppDatabase` entity/DAO accessor、`DataSourceModule` provider，并生成/核对 `app/schemas/40.json`。沿用 `scheduled_at`/`isDue()` 语义：未到点的信件显示为封存/待送达，到点后可打开且不自动消失。
   - 在 `WorldRepository` 增加信件创建、读取、打开和未读/待送达统计；用户在邮局页面创建信件，TA 通过 `world_write` 增加 `write_letter` action，并支持立即信或未来本地日期时间。两条入口共用同一仓库和同一调度服务，避免用户端和工具端规则分叉。
   - 新增 `WorldLetterScheduler` 与 `WorldLetterDeliveryWorker`：创建预约信后注册唯一 WorkManager one-time work，使用 `setInitialDelay` 尽量准时；到点 worker 标记 `notified_at`/送达状态并发通知，应用重启后 WorkManager 保留任务。创建失败、已过期或重复执行要幂等；若后续删除/改期，取消旧 work 再重排。
   - 复用 `NotificationUtil`，在 `RikkaHubApp` 创建世界信件通知 channel；通知无权限时仍保证邮局到点解锁，不让通知失败阻断内容送达。添加点击 PendingIntent 的世界邮局 deep link（携带 `assistantId`/letterId），扩展 `RouteActivity` 与 `WorldPage` 的初始页面/选中信件参数，使通知可直接进入 `postoffice.html`，而不是只打开封面。
   - 扩展 `WorldJsBridge.buildState`、导航和操作 API：`envelope` 返回两个入口的统计，`postoffice` 返回待送达/已送达/已读信件；增加创建信、打开信和刷新状态的桥方法。保持现有 WebView 池化、back/history 和 `imePadding()` 行为。
   - 调整 `home.html` 的留灯卡入口到 `envelope.html`，并实现新页面的返回、淡入、壁纸取色和响应式并排布局。邮局提供信件列表、封存倒计时/送达时间、打开详情、写信和预约时间控件；点击碎碎念入口继续使用现有 thoughts 页，不破坏现有 mailbox 抽取。

4. **打卡页键盘上移**
   - 在 `MoodCheckinPage` 用 `MomentsPage`/`WorldPage` 的 inset 方式，把 `.imePadding()` 放在拥有整页高度的外层容器上，而不是只加到输入框；保留 `Scaffold` 的 `contentPadding`。
   - 对位于 `LazyColumn` 中部的今日打卡表单增加 `BringIntoViewRequester`/焦点触发滚动，复用碎碎念/留灯等待键盘动画后滚动到 composer 底部的意图，确保文案和自定义 emoji 两个输入框都可见；如同页评论 `SocialCommentDialog` 也复现覆盖，再单独补 dialog 的 inset。
   - 验证 edge-to-edge、横竖屏、两个输入框切换、键盘收起后列表位置不跳变。

5. **自查、验证与交付前检查**
   - 每批改动后立即检查 imports、Room entity/DAO/迁移/schema/DI 一致性、WorldRepository 构造调用点、WorldTool 参数和提示词、JS bridge 返回值与 `pet.html`/新 HTML 的状态覆盖。
   - 运行针对性单测、`./gradlew :app:compileDistKotlin`/必要的 `test`，检查生成 schema 和 `git diff`；按 `ui-impl` 清单做 Compose/WebView/Room/消息工具链自查。
   - 用 browser-use 对 envelope/postoffice/cover 的桌面与移动尺寸截图自检，确认不空白、不重叠、键盘/返回/路由可用；实机覆盖安装前备份，重点验收 DB v39→v40、成年宠物冷却、头像首屏、预约信到点解锁+通知、打卡键盘。
   - 代码完成后再按仓库交付流程 commit/push/CI，提供最新 ARM64 APK、SHA-256 和镜像测速结果；本计划阶段不修改工作区。
