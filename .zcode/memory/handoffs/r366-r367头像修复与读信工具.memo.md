## Decisions

- [2026-11-27] **宠物头像空白先查“贴图是否已解码”，不要只怀疑合成层** — r365 把封面头像改 `<img>` 是另一条线；月团是宠物页 `.pdot` 的 `background-image`，根因是 boot 未等全部物种 `prepSheet`。修复=首帧前 await 全部 SPECIES，单图 `.catch` 不阻塞。
- [2026-11-27] **信件送达按收件人分流** — 用户写给 TA 的预约信 → TA 后台唤醒读信，不发用户系统通知；TA 写给用户的信 → 用户系统通知+深链。`notified_at` 语义改为“正确收件人已派发/无需派发”，避免旧行为把用户自己的信通知给用户。
- [2026-11-27] **`read_letter` 语义** — list 只给预览/待送达封存；read 才给全文；未到点拒绝；来自用户的信读后标记 `opened_at`（邮局显示已拆阅），助手自己的信不标记；无 id 默认最近未拆用户来信。
- [2026-11-27] **信件提醒不走 15s 世界动作去抖** — 每封信送达是独立事件，复用去抖会被别的动作挤掉；`notifyLetterDelivered` 独立派发。

## Pitfalls

- [2026-11-27] `getDueLetters()` 只返回 `notified_at IS NULL` 的信；升级前已送达的旧信不会补发到点提醒，验收必须写**新**预约信。
- [2026-11-27] 用户写给 TA 的信到点不再发用户手机通知；若 TA 选择沉默，用户端不会收到系统通知，只能进邮局看状态/聊天里问 TA。
- [2026-11-27] 后台唤醒依赖 WorkManager + 会话存在：助手已删除/世界开关关闭时直接视为已处理；没有会话时保持未通知，下次启动重试；app 被强行停止时等下次启动补发。
- [2026-11-27] 浏览器 mock 复现时本地文件加载太快看不出竞态；要用延迟响应（如 moon webp 延迟 1.5s）才能复现“首屏空白、点一下才出现”。
