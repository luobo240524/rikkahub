# r375 记忆行级召回与并入主线

## Summary

带进 prompt,模型不用再调 memory_read 才能看到内容。r375 出包验证编译通过,随后以 `[skip ci]` 并入
`custom-2.5.6`,没有重复占号。

## Pitfalls

- **必须先确认推送成功再 dispatch**:#373/#374 两个号是「编译 bug + 推送失败后仍 dispatch」双重原因,
  跑到旧 sha 上废掉的。正确顺序:推送 → API 校验远端 sha == 本地 → 才 dispatch。
- `github.com` 直连长期不稳(Connection reset / Empty reply / 21s 超时)。可用
  `-c http.curloptResolve=github.com:443:<IP>` 固定 IP 重试;今天有效过 `20.6.7.17`、`140.82.112.3`,
  失效就换,配合多轮循环基本能等到窗口。
- git 凭据:全局 `credential.helper` 指向 `gh.exe auth git-credential`,但 gh 未登录;改用
  `-c credential.helper= -c credential.helper=manager` 走 Windows 凭据管理器(存有 luobo240524)。
- 只含 paths-ignore 文件的推送不构建、不占号 —— 333e23bf 与 91391db3 两次均已实测。
- 编译期 API 踩坑:`String.replace(Regex)` 没有单参重载,漏 replacement 参数只会在编译期报
  NONE_APPLICABLE,写代码时按签名核对。
