# UI 预览(凡 UI 先出 HTML 预览)

## 硬规则

UI 改动一律先写 HTML 预览稿 → 用户确认 → 再写 Compose 代码(2026-11-07 用户定稿)。
**豁免(2026-11-21 用户明示):参数级小改动免预览**——限宽/间距/颜色/对齐/字号等微调直接改,
别做预览;新页面、新交互、整体视觉方案仍必须先预览。拿不准算不算小改动时,按用户当前语境判断
(用户直接给出精确行为规格的微调=小改动)。另有用户单次明示豁免的先例(r240 通话收纳卡睡前拍板)。
WebView 类需求走「预览即成品」:预览确认后 HTML 直接升级为生产资产,零还原损耗(先例:内心世界方案B)。

## 预览稿规范(每条都是真实翻过车的坑)

1. **首行 `<meta charset="utf-8">`**——宿主无 charset 线索时按 1252 解码,中文全乱码。
   经带 charset 响应头的本地服务器测试看不出来,内联宿主/文件直开才暴露。
2. **引用路径一律正斜杠**——反斜杠未转义 = 静默解析失败不内联。
3. **多屏预览:主题变量遍历所有 `.screen` / `.neu-screen` 元素逐一设置**——只设屏1曾致屏2竖线隐形。
4. **弹层/菜单 popover 必须实底**(用 card-solid 色)——半透明主题卡(星空 cardBg=7%白)做底会透视下层。
5. **坐标双轨拆开**:SVG 几何属性吃 viewBox 数值,HTML 覆盖层定位吃百分比;
   「百分比字符串」拼「px」是静默失效(left 非法被忽略,元素落到流位置被裁)。
6. 预览稿放 `.zcode/v2/visualizations/<会话或主题目录>/`;会话可视化目录(repo 外)的稿子
   实现前先拷进 repo 这里,不然下次找不到。

## 交付前自检(browser-use,不许裸交)

本机无 python、node 不在 PATH;起临时静态服务器用 Electron-as-node:
`ELECTRON_RUN_AS_NODE=1 "D:/zcode/ZCode.exe" <脚本.mjs>`(node v24,能 http 静态服务)。

- browser-use **不支持 file:// goto**,必须起 localhost 服务器再开。
- **fullPage 截图对超高页平铺错乱**——用 setViewportSize + clip 分段截。
- 自检点:中文无乱码 / 弹层实底 / 八主题逐个切换看一遍 / 交互(点词、戳、切换态)各点一遍 /
  截图对照确认后把结论(过了什么、什么没截)一并报给用户。
